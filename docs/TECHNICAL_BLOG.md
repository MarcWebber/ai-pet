# 让桌宠替你点按钮，最难的是点完以后

假设你让 JellyPet 发送一条消息。它找到发送按钮，点了一下，页面却没有及时显示结果。这个时候再点一次，消息可能发出两遍；直接说任务完成，也可能把失败留给用户。JellyPet 最近整理屏幕接管代码，处理的正是这个问题。

JellyPet 是一只住在 macOS 桌面上的果冻宠物。平时点它一下，可以截取当前屏幕并向本机 Agent 提问。打开接管开关后，用户交给它一个完整任务，本机已经登录的 Codex 或 TraeX 会读取页面，决定下一步做什么，再调用 JellyPet 的鼠标和键盘工具。

一次接管从观察开始。JellyPet 读取当前应用、窗口和页面元素，把按钮、输入框、文字等内容交给模型。模型看到的元素编号只属于这一轮，因为点击和滚动都可能改变页面。下一步操作到来时，程序会根据元素的名称、用途和所在区域重新寻找目标。找不到唯一目标，操作就不会执行。

普通点击完成后，旧的观察会立刻作废。模型必须重新看一遍页面，才能继续往下走。这条规则让动作和结果连在一起，也防止模型拿着上一页的编号继续点当前页面。

发送、提交、购买和删除要多走一小段。程序会在点击前刷新页面，先看看预期结果是否已经出现。结果已经存在，按钮便不用再点。结果尚未出现，程序记录当前按钮和页面状态，只执行一次点击，随后再看一遍页面。

第二次观察能确认成功，这条记录就被清除。第二次观察看不出结果，记录会留下来。只要页面没有变化，同一个按钮就不能立刻再点；等页面出现新内容后，重试才重新开放。这个限制保存在当前会话里，应用重启后无法保证同一次操作不会重演，所以真实的发送、购买和删除仍需在发布前逐项验证。

页面也可能一直没有前进。JellyPet 会比较相邻两次观察中的文字、元素和缩小后的画面。动作后连续六次看不到变化，连续十二次看到相同页面，或连续三次拿不到界面，接管就会停下。程序会把停止原因交给模型，模型只能说明已经做到哪里，不能继续盲点。

现有行为检查覆盖了三种情况。页面不变时，第二次点击被拦住；上一次操作确认成功后，同一个按钮还可以再次使用；页面发生变化后，先前不确定的操作也可以重试。Swift 行为检查、Release 构建和包资源检查已经通过。

这些检查仍然发生在测试环境里。真实模型往返、真实浏览器连接和完整桌面操作还没有验收，发送、购买、删除失败后的表现也没有实测。当前代码已经能阻止一些明确的重复动作，但它还没有得到可发布版本所需的真实页面证据。
